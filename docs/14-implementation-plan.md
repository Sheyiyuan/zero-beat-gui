# GUI 实施拆分与验收

本页是可执行的开发清单，补充[阶段路线图](07-roadmap.md)、[交互规格](13-product-and-interaction.md)和既有架构文档。依赖顺序以可运行的纵向流程为单位；类型绑定、SVG 和工具链准备不计为 GUI 播放闭环完成。0.8.0 继续保持未发布，待 GUI 完成与联合回归后发布。

## 当前实现进度

Session、RPC、原生启动、播放引擎及首批播放／重连修复已落地。本轮新增自绘窗口、主题、账号、歌单编辑／批量、内容浏览、歌词／片段、Android 文件访问、下载和同步流程。实现位置、回归证据及待设备验证事项统一见[完整功能验收](17-full-gui-parity.md)。下文保留各阶段验收目标，未列出的设备行为不能推定通过。

## 目录与所有权

当前代码组织：

```text
zero-beat-core/
  source/、media/、store/、player/、sync/   # 现有业务与数据
  session/                                # headless 编排与公开业务门面
zero-beat-gui/
  packages/zero_beat_core/                 # 纯 Dart 类型、JSON codec、契约样本
  tool/core-bindings/                      # Go 显式投影、生成器与样本验证
  tool/                                   # 本地环境检查与启动环境脚本
  design/                                 # SVG、token、浏览索引与渲染预览
  app/lib/
    app/                                  # 路由、主题、启动、平台生命周期
    core/                                 # 加载库、RPC transport、重连
    engine/                               # media_kit 与系统媒体适配
    features/                             # 共享状态与动作；desktop/mobile 分别实现视图
    shared/                               # 曲目行、分页、异步状态、动作菜单
  # Windows cmd/exe 后续
  rpc/、cmd/lib/                 # Go transport 与平台入口
```

Flutter feature 不直接 import FFI 库、不读写 SQLite、不持有平台 cookie。只有核心连接层取得令牌；只有引擎适配层接收带请求头的播放流。Go source 类型变化经显式 DTO 投影到 wire，再生成 Dart，禁止直接把 `store.Song` 默认 JSON 当公共协议。

桌面和手机使用两套界面组合与导航壳，复用类型、业务状态、资源与小组件，不用同一三栏 widget 按比例缩放。桌面鼠标优先，仅常用操作设快捷键；手机触控优先，不把 TUI 全键盘约束带入 GUI 验收。

## D0：工具链和契约基线

对应 P0 的前置条件，不需要先实现 GUI。

1. 在局部 shell 加载经过检查的 Flutter、JDK 与 SDK 路径，不改变系统默认 Java 或覆盖用户配置。
2. 固定实际使用的 Flutter/Dart 版本，记录 SDK 组件和 `flutter doctor -v`；Android 许可状态与设备状态分别列出。
3. 通过绑定生成器读取当前 core，生成 Dart 与样本；`-check` 必须能发现未重新生成的变化。
4. Go 测试检查投影、精度和秘密字段边界；Dart 静态分析与契约测试检查同一批样本。

**完成条件**：命令可复现、版本与路径明确、绑定检查通过；环境未通过的步骤有真实错误证据，不能用存在 SDK 目录代替可构建结果。

## D1：只读启动闭环

对应 P0 后半与 P1 第一部分。

- core Session 持有 app、store、controller 和串行任务队列；桌面先获取实例锁再开数据库，失败时逆序释放。
- GUI Go module 创建后消费 core 和绑定投影，入口提供 `ZeroStart` / `ZeroStop` / `ZeroFree`；Windows 后置为 sidecar。
- RPC 最先实现 hello、库列表／曲目读取、player snapshot、受控退出；鉴权、帧大小、超时、连接所有权从第一步就实现。
- Flutter 先完成 Linux 与 Android 空壳、路径解析、连接状态、曲库页和退出；macOS 在对应宿主验证。
- 首次启动空库显示真实空态；恢复已有库显示当前队列，但不自动播放。

**完成条件**：隔离测试库中启动、列曲、退出可重复；同数据目录第二实例不能开库；异常启动无锁泄漏。Flutter 能显示真实 Go DTO，不能只显示 mock 样本。

## D2：单曲播放与代次

依赖 D1；先不铺开所有页面。

- Session 接受播放操作并生成请求代次，解析在可取消 worker 中执行，完成结果回串行队列；来源、队列和重试逻辑继续使用 Go。
- RemoteEngine 把 load/pause/resume/seek/stop/volume 发送给 Dart；等待 ack 时 RPC 读循环继续处理响应，不能与 Session 互相等待。
- Dart 一个 engine owner 持有唯一播放器，安装 playback ID 后接收操作；每次异步回调都能归属原代次。
- 位置事件节流；ended/failed 保证不静默丢失。核心忽略旧代次、重复终态，自动重试最多一次。
- UI 完成底栏、正在播放、暂停 seek、当前作者入口；调试显示与用户显示分开，日志不含完整签名流 URL 或请求头值。

**完成条件**：两平台曲目真实播放；A→B 快切、旧 A 失败回调、同曲重试、重复 ended、暂停 seek、加载超时、核心断线均通过；断线重连拉快照且不自动重播旧命令。锁屏与响度真机验收仍见 P1。

## D3：曲库、搜索与保存

依赖 D2。先补本地数据闭环，再增加平台写入。

- 曲库类型标签、分页／虚拟列表、混合歌单展开与隐藏、本地歌单增删改；受限对象由核心校验。
- 搜索请求按 query/source/generation 过滤，合并搜索允许单源失败；旧 query 结果不能覆盖新 query。
- 通用曲目动作：播放、下一首、入队、加入歌单、打开评论／推荐／作者。
- 下载列表、账号与设置先接只读状态；写操作各自完成后才启用按钮。

**完成条件**：搜索结果进入本地歌单，重启仍在；正在播放与列表选择不同时动作目标正确；桌面鼠标／快捷键与手机触控操作分别通过，批量选择、失败重试可用；TUI 再打开同测试库数据一致。

## D4：评论、推荐、主页与电台

依赖 D3；共享字段与模型来自类型绑定，不额外创建平台 JSON 模型。

| 流程 | Go 能力 | GUI 实施要点 | 验收 |
| --- | --- | --- | --- |
| 评论 | `CommentReader.Comments` | Ref + 页码；只读正文；平台 notice；作者入口 | 首尾页、长正文、匿名预览、错误后重试 |
| 推荐 | `RelatedRecommender.Related` | Candidate 列表与通用曲目动作 | 播放、入队、下一首、保存 |
| 当前作者 | `Browser.TrackProfiles` | 按调用时曲目快照，去重并只列作者 | 单作者直达、多作者选择；播客电台不计作者 |
| 主页／集合 | `Browser.Browse` | 根据 BrowseRef / Track 互斥类型导航 | 分页、返回保存位置、加载中返回与迟到响应 |
| 电台发现 | `Browser.BrowseRoots` 与 `Browse` | 根入口→电台→节目→主播 | 节目播放、评论、保留 program 身份 |
| 链接打开 | `source.ParseBrowseTarget` | 明确的主页输入入口，错误在输入附近显示 | 用户／歌手／电台链接不当歌曲播放 |

「当前作者」过滤与单作者直达由会话／业务适配明确实现；不能让 Flutter 从含电台的列表中按显示文本猜。相关 RPC 名称见[接口约定](02-rpc.md)，本轮类型绑定不实现这些网络调用。

**完成条件**：桌面鼠标主流程与常用快捷键通过，Android 触控与独立返回栈通过；B 站风控单独记录为平台受限，不能通过 mock 验证声称真实内容成功；暂停和当前列表焦点不会改变「当前作者」的目标。

## D5：账号、下载、系统媒体与同步

分别依赖核心闭环，不要求全部塞进同一变更。

- 账号：扫码状态机、取消、过期冻结、重新登录；公开账号摘要与 cookie 分离。
- 下载：任务 id、进度、取消、原子落盘和索引恢复；Android 在无外部 ffmpeg 的真机验证 libav 封装、标签和离线播放；桌面继续使用既有完成处理器。
- 系统媒体：audio_service/媒体键只发送命令，Go 状态驱动显示，防止两套队列；Android 同进程后台服务复用同一引擎。
- 同步：读取配置、选择后端、首次初始化、默认关闭登录态、每设备启用、冲突选择、事务恢复；不在 Dart 实现快照或加密。

**完成条件**：登录→搜索→下载→飞行模式播放；锁屏 30 分钟、蓝牙／耳机／焦点打断；GUI 与 TUI 的临时双设备同步验证 v2/v3、排除记录、仅本机保留、并发冲突和再次同步无变化。桌面真实账号数据只在用户选择后使用，自动回归使用隔离目录。

## 测试分层与验证命令

| 层次 | 核心断言 | 不能替代 |
| --- | --- | --- |
| Go 投影／生成器 | 当前类型到 wire 的字段、单位、枚举、精度；生成漂移 | RPC 生命周期和真实源请求 |
| Dart 契约 | 样本解码、round-trip、未知值／缺字段／null策略 | Flutter 布局或音频 |
| Flutter widget | 焦点、输入保护、长文本、异步状态、语义标签 | 真机系统媒体和网络 |
| RPC + Session | 代次、取消、超时、双向调用、重连、锁与恢复 | media_kit 的平台行为 |
| 构建后集成 | 真实 GUI 二进制操作与 TUI 数据互通 | 未测试平台安装与签名 |
| 真机／桌面手工 | 出声、锁屏、耳机、输入法、系统键、安装 | 其它平台的相同能力 |

类型绑定检查从集成仓库执行 `make check-gui-bindings`，具体命令与生成覆盖清单见 [Dart 包文档](../packages/zero_beat_core/README.md)。本机环境检查命令见[开发环境记录](12-development-environment.md)。Go/TUI 原有检查仍由集成仓库 `make check` 执行；新增 GUI 契约检查不能因为 Flutter 不在 PATH 而静默跳过，必须明确报出缺少工具。

2026-11-17 本轮准备验证记录：

- `make check-gui-bindings` 通过：37 个 DTO、9 个开放枚举；Go 测试、生成漂移检查、Dart 静态分析与 45 个跨语言样本／93 项检查通过。绑定子任务另完成 Go race tests、vet 与 Dart 格式检查。
- 九张 SVG 均完成 XML 解析与 PNG 渲染；桌面与移动端分别人工检查。预览索引链接与 token JSON 通过检查。
- 本地 Markdown 链接和差异空白检查通过；站点同步脚本通过 JavaScript 语法检查。
- 文档站完整构建未通过验收：沙箱中 Node 调用只读 Git 子进程返回 `EPERM`；放宽沙箱的自动审批服务返回 HTTP 429，命令未执行。Android APK 同样待补验，细节见环境记录。未部署站点或创建发布。

每个阶段记录：提交或工作区标识、工具链版本、设备／系统、命令、样本、预期、实际、未覆盖项。测试脚本不能把失败转成 warning 后输出成功。

## 联合发布门槛

GUI 页面、播放和平台验收完成后，重新运行 TUI 全量回归及关键 PTY 流程，补齐 GUI/TUI 共用数据库、默认关闭登录态、同步冲突和数据恢复检查。最后生成安装包、核对动态库／第三方许可、签名与校验和，并更新正式说明。

D0 类型绑定完成不表示 P0 整体完成；SVG 设计完成不表示 P2 页面可用；SDK 安装完成不表示 Android 真机播放通过。正式发布前，README 与路线图按实际验收结果更新，不提前创建 core/TUI 0.8.0 发布标签。
